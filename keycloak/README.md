# Keycloak Configuration

This directory contains the source-controlled VDIForge Keycloak configuration for Phase 5.

## Realm

Authoritative realm source:

```text
keycloak/realm/vdiforge-realm.json
```

The Helm chart imports an identical copy from:

```text
helm/vdiforge/files/keycloak/vdiforge-realm.json
```

The Phase 5 static validator fails if those files differ.

## Included Objects

The realm import defines:

- realm `vdiforge`
- public OIDC client `vdiforge-frontend`
- API audience client `vdiforge-api`
- realm roles `vdi-user`, `vdi-developer`, `vdi-devops`, and `vdi-admin`
- demo identities `demo-user`, `demo-developer`, `demo-devops`, and `demo-admin`

The browser client uses Authorization Code Flow with PKCE S256. It does not use a client secret, implicit flow, direct access grants, wildcard redirect URIs, or wildcard web origins.

## Secrets

Do not commit real passwords, client secrets, TLS private keys, or generated realm exports containing secrets.

Runtime-only values are generated by:

```bash
bash scripts/phase5-create-local-secrets.sh
```

That script stores local values under ignored `.local/phase5/` paths and creates Kubernetes Secrets in the `keycloak` namespace.

The example file [local-secrets.env.example](local-secrets.env.example) documents expected variable names only.
